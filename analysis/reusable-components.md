# 三道题验证后的复用边界

## 已落地

- **统一关卡模型**：Puzzle 提供尺寸、区域、可站立格、物体和人物；第一题与 Frontier Town 共用地图、人物卡和回放。人物不再固定为六人，地图支持6×6、10×10 与 16×16 三个实例。
- **可逆步骤回放**：步骤使用候选初始化、移除和落位动作；每次导航从预计算快照读取，回退不会泄漏后面的答案。理由包含线索引用和前序步骤依赖。
- **分层讲解阅读器**：主线只说本阶段结论；“为什么”展开后每次展示一条细讲，可前后翻阅，主地图保留本阶段状态。细讲目前不独立回放中间地图动作，这是下一轮体验评估点。
- **关卡选择**：统一 catalog 管理三个独立路径，`/` 是题目入口，旧 query 链接自动跳转。
- **独立验证**：新增基于地图谓词的约束搜索，检验第二题解的唯一性；教程生成时每次落位要求候选单一，最后才与源 JSON 答案核对。

## 最值得继续抽取的推理组件

1. `beside`：同区域、曼哈顿距离 1；可站立检查单独处理。
2. `corner`：上下至少一面墙、左右至少一面墙，支持凹凸区域，不能用区域包围盒四角替代。
3. `unsupportedCandidate`：若目标格与某人物所有候选都行列冲突，则可排除。它统一了 Etta 三候选与 Garrett / Bessie 二候选的交叉格推理。
4. `reservedRows`：k 人的候选只覆盖 k 行，则其他人不能用这些行；本题为 Etta / Ivy 的两行锁定。
5. `identitySupport`：把特殊身份、同区关系、家具条件与各人的个人线索联立，列出有支持的组合。身份与凶手是两个字段，不能等同。
6. `proofToLesson`：机器验证的原子排除与玩家阅读的主线不是同一粒度；允许多条排除合成一步，但每一步必须能展开依据。

## 暂不冒充通用的部分

- 两种源 JSON 的坐标、字段、物体拼接分别适配；第一题解析器仍是专用。下一次抽取需保留版本检测和失败即停，不能猜字段。
- 第二题家具按逐格素材展示，未还原原站所有拼接家具与旋转。地图占格与推理正确，视觉仍可细化。
- 区域标签现支持关卡数据配置；特殊身份条件与中文讲解仍是案件配置或专用逻辑；尚不是自动解任意 Murdoku 的求解器。
- 原站难题页面在本次访问显示 Puzzle Not Found，但公开 JSON 可读取。原始 JSON 保存在 sources/frontier-town.json。

## Skill 草案应记录的工作流

取得公开 JSON → 版本适配 → 验证坐标与物体语义 → 从线索生成候选 → 构造有证据的排除链 → 独立验证唯一性 → 只在末尾核对官方答案 → 压缩为主线与细讲 → 接入共享回放 → 检查桌面、手机和反向回放。

本次结果：官方 7 条压缩提示 → 17 个主线阶段 + 48 条可选细讲。先让用户体验第二题，再决定是否把流程正式安装为 skill。


## 专家题的新增验证（The Zoo）

- 21 个主线阶段、68 条可选细讲；无需试猜，所有落位经唯一候选断言后才写入步骤。
- 地图支持水域子区域归属、逐格底色/纹理、2×2 物体占格、自定义区域标签和物体名称。
- 人物支持角色标签与最多四行的纵向人物卡布局（16 人为 4×4），沿用共享头像、选择样式和完成对钩。
- 教学可指定 `candidateCharacters`，把“关联证据人物”与“地图要显示的候选人物”分开；人数概览不用覆盖满屏候选。点击人物仍可查看其全部候选。
- `catalog.ts` 将标题、简介、题目、步骤、难度与路由集中配置；新增题目无需继续增加 main.ts 条件分支。
- 可进一步抽取 `reservedColumns`（3 人锁 3 列）、`regionCapacity`（8 人覆盖 6 区，两对恰好耗尽余量）、`relativeRowSupport`（两人恰好相邻行）。目前求解谓词仍保留于关卡生成脚本，不声称已经是通用规则引擎。
- 水域不能被误当新房间；大物体覆盖格要同时用于绘图、可站立判断和邻接判断。源数据中旧 solution_text 写 C7，当前 player_hint 和实际地图一致为 C8；已按地图验证，没有照抄旧提示。
- 桌面 1280×720、1440×900 检查一屏展示；390px 手机布局检查无横向溢出。细讲仍与主线共享地图终态。
